# Draft immutable parser image contract

Status: candidate only; no production authorization or refinement claim. Existing revision6 and all current280 model claims remain unchanged. The authoritative280 registries are inherited112, document125, field order14, associativity16 and partial types13; preserve their exact types and source hashes. Require two Terra, two Sol and two Astra reviews of the frozen candidate before any production change; resolve findings, freeze hashes, and perform two clean Lean builds plus independent runtime checks before considering promotion.

Every client PostgreSQL SQL byte still traverses the parser built from /home/augustus/SQLeanParser. Preserve exact UTF8 source, response framing/derivation/profile/commit checks, classification, lexical barriers, prepared provenance, limits and fail-closed routing. No direct database path is introduced.

The proposed identity is the live sealed image, not the current pathname. At gate creation, open the owned binary once; copy bounded chunks into a private memfd created with sealing enabled, close-on-exec initially enabled and explicit MFD_EXEC required; absent binding/kernel support denies without fallback. Handle short writes and errors. Do not use shared writable mappings. Apply WRITE|GROW|SHRINK|SEAL together, verify all required seals and exact size, THEN hash the sealed destination using offset-independent reads. Require the pinned lock SHA256 and nonzero expected size before publishing any gate/cache state. Hashing the source during copying is insufficient: concurrent source modification can produce a mixed snapshot; hashing the final sealed destination against the pin rejects every nonmatching snapshot under the existing SHA256 assumption. Reject unsupported kernels, execution policy, sealing errors and resource exhaustion without fallback.

Retain the image fd privately for the gate lifetime. A numeric fd alone is not object identity. Serialize close/replacement with admissions and child launch; duplicate the live image under that lock for each operation. Verify fstat device/inode/size against the initialized image and F_GET_SEALS required bits on the duplicate before every admission, including cache hits. No other code owns/closes/reassigns the private handle. Closing invalidates the gate and clears its cache; never reopen the pathname or recycle a gate identity. All unexpected fd/fstat/fcntl/dup errors deny. Concurrent validation after close denies. This ownership discipline is a trusted adapter obligation.

On misses, pass the duplicated fd with subprocess pass_fds through the existing prlimit invocation and execute /proc/self/fd/N; N must name that inherited duplicate in the process that performs exec. Use an absolute reviewed prlimit path, retain AS=1GiB, CPU=6s, wall=5s, output16MiB, two parser slots and max-transitions1000000. Never resolve the original parser pathname at execution. Probe descriptor survival through prlimit and /proc/self/exe identity in an isolated witness executable; test the actual ELF as well. Direct execveat/fexecve requires an explicitly reviewed launcher if adopted instead. No Python preexec_fn in the multithreaded service. Missing procfs or failed descriptor execution denies; no pathname fallback.

Cache request identity includes exact SQL bytes, pinned image digest, profile, commit, policy and gate generation. Successful decisions retain immutable classifications; failures never enter acceptance cache. An old generation cannot populate or satisfy a new generation. Preserve bounds256 entries/4MiB SQL. Seals establish immutable image bytes only; successful report checks remain mandatory for fresh admission.

DISK REPLACEMENT POLICY REQUIRES EXPLICIT CONTRACT CHANGE: revision6 currently denies a changed pathname on every admission. This candidate continues serving the initialized pinned sealed bytes after the pathname changes or disappears, until explicit gate shutdown/reinitialization. It cannot claim revision6's live-path tamper-denial behavior. Restart/new gate reads and checks the current pathname and denies mismatches. If per-admission disk tamper detection is required, this candidate is unsuitable without a separate reliable mechanism; stat-only identity does not prove byte equality.

The131MiB image consumes additional process/system backing memory for the gate lifetime (136492600 bytes here), even when it is not mapped into the proxy address space. Child RLIMIT_AS constrains virtual mappings in the child, not total parent/system backing memory; account for memfd pages, parser mappings/heap and output buffers separately. Do not claim the existing1GiB child AS limit caps aggregate memory. The parser is dynamically linked; this pins executable bytes, not dynamic loader/libraries/kernel. Existing platform trust remains explicit.

Lean scope: abstract immutable-byte preservation and exact-request/cache refinement conditional on initialization, syscall observations, fd ownership and kernel semantics. It does not prove Linux, SHA collision resistance, Python implementation, procfs/prlimit correspondence or dynamic dependencies. Runtime witnesses must establish these independent finite surfaces. No axiom or sorry is allowed in candidate Lean.

Required checks before promotion: sealed destination pinned hash; source-copy race rejection; WRITE/GROW/SHRINK/mmap mutation denial; missing seals and wrong size denial; closed/reused fd denial; dup/close concurrency; child fd/executable correspondence; parser success and malformed/failure/timeout cases; cache exact-byte/profile/policy/generation negatives; altered/removed disk policy; unsupported kernel/procfs/noexec fail closed; bounded memory accounting; existing model claims remain registered and pass unchanged. Benchmark only after correctness, compare real CLI read and ownedIds and cache-hit latency with declared sample counts.

Seals belong to the inode, cannot be removed, and WRITE alone does not prohibit resizing. FUTURE_WRITE is not an acceptable substitute for WRITE.

## Review amendment r2: bounded initialization and immutable interpretation

The deployment pin includes trusted expected size136492600 bytes and binary SHA2569b252aabef502a9471f64c60ad2b0821e9db209a275c7ba8a4bd01da275e0cf7, frozen with the reviewed candidate rather than inferred from the source's current fstat. The ordered3285-entry production_lhs mapping has SHA256679284527c19f215a3b6a46c2ac107bbb152959ffd44fe3108f198f8f4a55eeb over UTF8 compact JSON with ensure_ascii=false, separators comma/colon. Production implementation requires this expected-size pin to be installed in its reviewed immutable configuration; absent pins deny. No existing config file is changed by this draft.

Initialize at most one candidate image per gate through one supervised, short-lived initializer process (not a persistent parser worker). Parent enforces5seconds wall deadline and the initializer has CPU6seconds, AS256MiB, core0 and at most one source/image/transfer descriptor set; supervision kills and reaps the helper on timeout/cancel/error. A helper may block in a kernel syscall; no service gate/cache is published while it runs, and startup never waits past its deadline for helper success. Uninterruptible kernel I/O teardown itself remains kernel trust; no hard real-time OS claim is made. Open the owned source with O_RDONLY|O_CLOEXEC|O_NONBLOCK|O_NOFOLLOW, reject anything other than a regular file before reading, and verify its initial size matches the trusted size. Bound total read/copy to exactly that size, with reads of at most min(1MiB,remaining), handle short writes, reject early EOF and probe exactly one further byte to reject excess/growth. Initial fstat is only an early rejection, never the bound. Close the source before sealing. Seal destination, verify all four seals and exact size, hash that destination after sealing and require the frozen digest. Transfer only the resulting sealed descriptor with a strict bounded private SCM_RIGHTS message; parent validates exactly one received descriptor, size/object/seals and the helper's successful pinned-digest result before publishing. Both processes close every owned source/image/socket/received descriptor on every failure; close unexpected ancillary descriptors too. Publication is atomic and no partial cache/status generation survives a failure. This new one-shot initializer and ancillary-fd validation are explicit runtime TCB and test obligations, not covered by the Lean model.

Build one private deeply immutable validated ConfigSnapshot before initialization: binary SHA256, trusted expected size, profile, PostgreSQL commit, ordered production mapping as an immutable tuple, mapping digest, policy, and unique monotonic gate generation. Strict duplicate-key/type checks and exact pinned profile/commit/mapping digest are mandatory. Snapshot has no mutable aliases, public setters or late lock reload. Use exactly this snapshot for initialization, report interpretation/production classification, immutable native decision construction, cache keys/checks and status. Cache identity includes all snapshot fields (direct equality or a collision-resistant canonical snapshot digest with unambiguous encoding), as well as exact SQL bytes; generation alone never licenses altered interpretation. Any intended interpretation change creates a new generation with empty cache and separately reviewed pins. Disk lock changes during a running generation do not change it; status explicitly reports config_policy=frozen-until-new-generation and disk_policy=restart-check-only. Status is captured atomically under the same lifetime lock and reflects actual current lifecycle; it returns immutable scalar/copy data only. Child environment remains exactly sanitized LEAN_NUM_THREADS=1 and PATH=/usr/bin:/bin, with no inherited loader overrides.

## Review amendment r2: bounded descriptor ownership

At most one lifetime-check transient duplicate exists per gate: create/check/close it while holding the private lifetime lock; hits never retain it outside the lock. A cache hit checks the immutable snapshot, generation/live state, object/size/seals and returns its immutable decision in that same critical section. A close linearizes under that lock, marks generation stopped and clears cache. Operations already returned before that point remain prior completed admissions; no claim of revoking already forwarded SQL is made.

Miss waiters hold no image duplicate. First acquire one of the existing two parser slots with bounded cancellation/shutdown-aware wait; then acquire lifetime lock, recheck generation/live/snapshot and duplicate the original image. The slot owner exclusively owns that reserved duplicate until subprocess launch/inheritance completes, and retains ownership until child completion for simple uniform cleanup. At most two reserved execution duplicates plus one transient check duplicate and the single private image descriptor may exist; initializer resources are disjoint and forbidden once live. Never expose a reserved descriptor to gate.close or any other closer. Child launch uses the reserved fd number only while its unique owner holds it, passes it explicitly through pass_fds and inherits it before any owner close. No fd is retained by waiters, no fd is stored in cache, and no slot is held while waiting for a lifetime lock owner to wait on a child. Lifetime lock is released before subprocess I/O/wait.

Every slot owner uses finally/RAII to kill and reap an unfinished child, close the reserved duplicate and release exactly its own slot on success, parse rejection, timeout, caller cancellation, output failure, launch error or shutdown. Gate.close marks stopped and invalidates cache under lock, releases lock, then cancels/reaps registered children and wakes all waiters without holding the lock while waiting; registered reservation owners perform cleanup, and close never closes their numeric fds. Waiters awakened after shutdown deny without duplication. After parser completion, reacquire lifetime lock and recheck live generation and exact snapshot before insertion or returning an accepted decision; stale work denies and cannot populate a new cache. Gate.close waits for registered owner cleanup before reporting shutdown complete; cancellation/shutdown never silently reports cleanup complete while children/resources remain. Temporary resource cleanup failure is infrastructureFailure and remains visible as failed/shutdown-incomplete, with no acceptance or new gate publication. Required exec noexec policy cannot be weakened by flag fallback, sysctl changes, interpreter invocation or disk execution.

These amendments resolve T1-01, SQLIM-S1-01 and SQLIM-A1-01 at plan level. Their runtime implementation remains unexecuted. The seven conditional Lean facts and all280 unchanged model claims do not prove these OS/lifetime/config requirements.
